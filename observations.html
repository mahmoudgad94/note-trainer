Engineering notes on Musicca

What I noticed on Musicca

Six practical opportunities I noticed while reviewing the public exercise experience.

1. Audio library

The exercise pages load Howler.js 2.0.9, released in 2017. Upgrading to Howler 2.2.x fixes autoplay-unlock and Safari/iOS AudioContext issues that ear-training exercises commonly encounter. I would treat this as a contained, low-risk first task: update the library, verify playback and unlock behaviour across supported browsers, and ship it independently. This demo uses Howler 2.2.4 with the same sample-based approach.

2. Legacy structure

The exercise system lives under /ovelser/, uses Danish file names such as side_opsaetning and generelt, and exposes a global Musikipedia object. That structure argues for careful modernisation in place, using small, reviewable commits that preserve working behaviour rather than a rewrite. This approach also matches the job description's intent.

3. Input methods

The exercises are answered by clicking. Adding Web MIDI support for USB and Bluetooth pianos would let students answer on a real instrument, as this demo shows. I would add it as an optional input path into the existing answer flow, preserving the current controls so it degrades gracefully where unsupported; on iOS, students would continue using the on-screen keys.

4. Locale context leak

English exercise pages, including /exercises and /exercise/16, are served with html lang="en", but their embedded Joomla script options contain Russian JLIB_FORM_FIELD_INVALID text and a keepalive URI pointing to /ru/component/ajax/. This is a low-risk, high-signal first task.
Fix: Build Joomla text and keepalive options from the active request locale and add response-level regression tests for representative language routes.

5. Search engines are blocked from rendering assets

robots.txt disallows /components/ and /modules/, yet public exercise pages load CSS and JavaScript from com_parentcontrol and mod_leaderboard under those paths, so crawlers render the pages without them.
Fix: Allow the public asset subpaths while keeping genuinely private routes blocked.

6. Multilingual sitemap and hreflang issues

The robots-declared sitemap at /sitemaps/sitemap.xml contains invalid values such as hreflang="exercises" and hreflang="*" with literal /*/ URLs, has no lastmod or x-default, and exposes 493 pages while /sitemap.xml exposes 439. For a site in 21 languages, this affects how translated pages are discovered and ranked.
Fix: Publish one authoritative, BCP 47-valid sitemap from a locale-aware generator, with consistent canonicals and reciprocal hreflang on pages.

These six outside-in observations are based on the public site and verified in the browser; happy to be corrected on internals.
